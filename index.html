How the fairness works

A 32-byte server seed is generated locally and immediately hashed. You publish SHA-256(serverSeed) — the commit — plus the roster, game and winner count, all squeezed into one Draw ID. At that point the outcome is already fixed but unknown to everyone, including you.

The crowd then supplies a client seed. Every random decision comes from HMAC-SHA256(serverSeed, clientSeed:nonce:blockIndex), read as a byte stream, with rejection sampling so there is no modulo bias.

After the draw you reveal the server seed. Anyone can hash it to check it matches the commit, then replay the exact same animation and get the exact same winner. Change one name, one character of either seed, or the game mode and the Draw ID or the replay stops matching.

Not covered: this proves you didn't rig the number. It does not prove the roster was complete or that the entrants are real people — publish the Draw ID somewhere timestamped and public for that.
